Minimal repro — canvas 2D font matching depends on document attachment

With a user-installed font (i.e. not part of the macOS system set — e.g. Google's "Noto Sans JP" variable font placed in ~/Library/Fonts, or a font bundled by an application such as Microsoft Office's "YuGothic"), the identical ctx.font string resolves to different font faces depending on whether the canvas element is attached to the document. Both measureText and fillText follow the mismatched face, so text measured on one kind of context and painted/laid out via the other gets clipped. No warmup, transform, or drawing is required.

Every context is measured twice: with the target family, and with a nonexistent family ("NoSuchFont-Control-7f3a9", sans-serif) as a per-context generic-fallback baseline. This separates two distinct failure modes: a named-family visibility split (the named family matches only on some contexts — observed in WebKit) vs a generic-fallback split (even the nonexistent family measures differently, i.e. generic resolution itself is context/language-dependent — observed in Firefox). The div[lang=ja] / div[lang=en] and iframe rows probe language inheritance as the driver of the latter.

To reproduce the WebKit issue, install a font that is not in the system set and enter its family name below (default assumes Google "Noto Sans JP" in ~/Library/Fonts).
